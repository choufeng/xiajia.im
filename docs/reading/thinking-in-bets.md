## 关于本书

| | |
|---|---|
| **书名** | 《对赌》（*Thinking in Bets*，又译《对赌：信息不足时如何做出高明决策》） |
| **作者** | 安妮·杜克（Annie Duke） |
| **首版** | 2018 年 |
| **类型** | 决策科学 / 行为心理学 |

作者是认知心理学博士（宾大），却以职业扑克选手身份闻名世界——拿过一条 WSOP 手链，奖金榜常年前列。这本书就是把「扑克牌桌上学到的决策直觉，翻译给所有人用」。核心立场一针见血：**我们习惯用结果倒推决策对错，而结果里掺了大量运气。** 大部分时候，你骂的不是「决策错」，而是「运气差」。

它和《思考，快与慢》是姊妹篇——卡尼曼讲大脑怎么出错，安妮讲在出错的前提下怎么下注。读完两本，你的决策框架才算完整。

## 核心框架：决策质量 ≠ 结果质量

全书围绕一个公式：

```
结果 = 决策质量 × 运气
```

决策质量 = 在当时可得信息下，选 EV（期望值）最高的行动。运气 = 你控制不了的所有因素。两者相乘才是你看到的结果。

**问题来了：你只能观察到结果，看不到决策质量和运气各自占多少。** 于是大脑偷懒，发明了「结果论（resulting）」——好结果 = 决策对，坏结果 = 决策错。这是全书要拆的第一个、也是最致命的认知陷阱。

> 工程师视角：上线后出 bug，你第一反应是「这设计有问题」。但 bug 可能来自当时合理、事后才暴露的边界——决策在当时信息下没错。**先拆「决策质量」和「运气（新信息）」，再决定要不要改设计。** 不拆就推翻重来，是用结果论制造第二个 bug。

下面五条，是安妮给的「在不确定上下注」的核心武器。

### 把「我确定」改成「概率 X%」

**概念**：任何信念都是对未来下的注。不说「这事一定发生」，改说「我认为发生的概率是 70%」。

**为什么**：「确定」是大脑省力的产物，不是真相。世界本质不确定，逼自己说一个百分比，就把隐藏假设摆到台面。一旦数字落到纸上，你就没法自欺——「70%」和「99%」对应的行动完全不同。

**怎么做**：预测任何事前，先估一个概率区间。事后回看，校准你的「概率感」准不准。长期记录会发现：你说「90% 确定」的事，实际可能只有 60% 发生——这就是需要校准的地方。

> 工程师视角：估工时别说「这周肯定做完」，改说「80% 概率周五前完成，20% 拖到下周」。数字一摆，风险立刻可见，排期也更诚实。

### 枚举「可能未来集合」

**概念**：下注前，先列出所有可能的结果，不只赌「最可能那个」。

**为什么**：只赌一个未来 = 孤注一掷。枚举多个未来，你才能算每个行动的期望值，选 EV 最高那条。扑克高手每一手牌都在脑里跑「对手可能持哪几手牌 × 每手对应我该怎么打」。

**怎么做**：做技术选型前，列三条——「最可能发生 / 中性情形 / 黑天鹅」。给每条估概率和后果。这样选出来的方案，是兼顾多数情形、扛得住意外的，不是只赌顺境的。

> 工程师视角：写方案前列「故障树」——数据库挂了、依赖服务超时、磁盘写满……每条都想好降级路径。这套枚举，和安妮的「可能未来集合」是一回事，都是逼大脑别只看 happy path。

### 求真小组（Truth-seeking Group）

**概念**：找几个能直言「你这个决策哪里有问题」的人，定期互评。

**为什么**：一个人没法校准自己——动机推理（相信想信的）+ 自利偏差（成=我牛，败=运气差）是默认设置。需要外部视角把你从叙事里拉出来。但普通「同好群」只会互相安慰，求真小组的核心是**允许互相质疑决策、不质疑动机**。

**怎么做**：组要小（3-5 人）、要信任、要有共同语言。复盘时不问「你为什么这么选」（质问），问「你当时基于什么信息这么选」（求真）。安妮用「蜡烛 vs 火炬」区分两种心态：**蜡烛**主动照亮盲区（求真 / skeptical），**火炬**只确认已有信念（确认偏误 / confirmation）。

> 工程师视角：code review 就是技术版的求真小组。烂 review 只挑风格，好 review 质疑「你这个抽象为什么需要、边界 case 想过没」。review 文化健康，团队决策质量才上得来。

### 心智时间旅行（10-10-10）

**概念**：决策前，分别想象 10 分钟后、10 个月后、10 年后的自己会怎么看这个选择。

**为什么**：当下情绪会绑架判断——愤怒时回邮件、恐惧时砍仓位、兴奋时签合同。把视角拉到三个时间尺度，当下的情绪权重就被稀释，长期利益浮上来。

**怎么做**：纠结时问自己三句——「10 分钟后我会后悔吗？10 个月呢？10 年呢？」。三个答案不一致时，偏向长期那个。

> 工程师视角：熬夜写完一段「能跑但丑」的代码，当下爽（10 分钟）。10 个月后接手的人（可能就是你自己）会骂。10-10-10 一套，技术债决策立刻清醒。

### 决策日记，对抗后见之明

**概念**：做决策时立刻记下——基于什么信息、估了什么概率、预期什么结果。事后别改。

**为什么**：大脑有「后见之明（hindsight bias）」——结果出来后，记忆会自动篡改，让你觉得「我早知道」。决策日记锁住当时的真实判断，逼你按「当时信息」复盘，而不是按「现在结果」编理由。

**怎么做**：每个重要决策记三行——信息 / 概率估计 / 决策依据。定期回看，校准你的判断力有没有进步。

> 工程师视角：技术选型时记日记——「选 X 不选 Y，因为假设了 A、B、C」。半年后 A 不成立，你能立刻识别这是「假设变了」不是「当时选错」。没有日记，你会把所有事后的不适都归因为「当时傻」。

## 反例对比表

| 直觉法（结果论） | 下注思维 | 差别 |
|---|---|---|
| 结果好 = 决策对 | 拆「决策质量 × 运气」 | 好结果可能是运气，坏结果也可能是运气 |
| 「我确定会这样」 | 「概率 X% 会这样」 | 把隐藏假设摆上台面 |
| 失败就全盘否定 | 分辨是决策错还是运气差 | 同一决策可能多次坏结果 |
| 成=我牛，败=运气差 | 客观归因（含运气） | 不让自利偏差扭曲学习 |
| 当下情绪决策 | 10-10-10 三视角 | 长期利益优先 |
| 「我早知道」 | 决策日记还原当时信息 | 按当时信息复盘 |

一句话：**凡是让你「确定」「归因简单」「事后诸葛亮」的，多半在骗你；凡是逼你说概率、拆运气、记当时信息的，才在帮你真正学会决策。**

## 我的思考

### 1. resulting 是工程师最常掉的反模式

我复盘过自己一堆「事后觉得蠢」的决策，发现大半其实在当时信息下是合理的——是结果差让我给它扣了「蠢」的帽子。不拆运气，就会把好决策当坏决策扔掉，下次遇到同类情形反而更慌。读完这本书我开始养成习惯：复盘先问「当时基于什么信息」，再问「结果里有多少是运气」。**这样才不会因为一次坏结果，推翻一套本来对的方法论。**

### 2. 把「我确定」改成概率，治好了我的过度自信

我以前估工时、估风险、估市场反应，张口就是「肯定」「绝对」。逼自己说百分比后，立刻发现——我说「90%」的事，实际命中可能只有 60%。**校准概率感，比追求「说得更准」更值钱**，因为它先暴露你哪里过度自信。这套校准，工程师做容量规划、上线评估都用得上。

### 3. 决策日记是技术债的「时间戳」

技术选型最容易在后年被骂「当时为什么选这个」。但骂的人（包括未来的自己）用的是后见之明。决策日记把当时的假设锁死——半年后某个假设失效，你能清楚识别「这是假设变了，不是决策错」，然后定向调整，而不是推倒重来。**没有日记，所有后年的痛苦都会被归因为「当时傻」，这是最浪费的学习方式。**

## 一句话总结

> 别问「结果对不对」，问「当时信息下这个决策是不是最优」——把运气从结果里拆出来，才算真正学会决策。
