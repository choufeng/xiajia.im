# 稻草人谬误

> 你赢的不是那场辩论，是你自己扎的稻草人。

---

## 一句话定义

**歪曲对方的观点 → 攻击被歪曲的版本 → 宣称自己击败了对方原意。**

打倒一个假人，假装打倒了真人。这种假人就是「稻草人」——它看着像对手，其实是你自己编的、最容易被打倒的版本。

## 它长什么样

| 对方原意 | 稻草人版本（被歪曲后） |
|----------|----------------------|
| 「教育经费应该多投一点」 | 「你是说要不顾一切无限砸钱，连国防都不要了？」 |
| 「这个需求我需要再想想」 | 「你就是不想干、想摸鱼」 |
| 「代码要写注释」 | 「你是想把每行都写满废话注释？」 |
| 「我支持环保」 | 「那你别用电别坐车，去山里住啊」 |

注意那个套路：**把「适度」偷换成「极端」，把「部分」偷换成「全部」，把「有条件」偷换成「无条件」。** 然后对着极端版本猛打。

## 为什么这么好用

因为它**省力**。

理解对方真实观点要费脑子，要站在对方立场想。而把对方观点推向极端，只需要一个动作：加个「所以你的意思是……」。

而且它特别**容易煽动观众**——极端版本听起来荒谬，围观的人一听就觉得「对方太离谱了」，立刻站到你这边。于是赢了场面，输了真相。

更深一层：**很多人不是故意歪曲，而是真没听懂。** 大脑会自动把模糊的对方观点「补全」成自己熟悉的样子，而熟悉的往往是极端版。这是认知偷懒，不是恶意。

## 怎么识别与破解

### 听到时（你是被歪曲的一方）

第一步永远不是反击，而是**把原意钉死**：

> 「等一下，我的意思是 X，不是 Y。请按 X 来回应。」

把 X 写下来、重复一遍，让对方无法继续打稻草人。稻草人谬误一被点名，当场失效。

### 说到时（自查是不是在扎稻草人）

开口前问自己一句：**「对方真的说过我即将反驳的这句话吗？」** 如果没有，先复述对方观点，复述完等对方点头「对，我说的就是这个」——再开始反驳。

这一步叫**钢铁侠（Steel Man）**：把对方观点还原到最强版本再去打。能打倒最强版本，才算真赢。

> 三秒自检：我现在打的，是对方说的话，还是我脑补的话？

## 工程师视角

技术评审里稻草人特别多：

> A：「这块我觉得可以引入缓存，访问太慢。」
> B：「所以你想给所有接口都加缓存？那数据一致性问题你负责？」

A 只说了「这块」加缓存，B 把它放大成「所有接口」。真问题（这块要不要缓存、怎么保证一致）没被讨论，反而吵起了「要不要全盘上缓存」这种不存在的问题。

破解：**把范围写下来。** 评审白板上写下「讨论对象 = 接口 X，非全量」。稻草人没了土壤。

架构选型同理——「你选微服务？那单体里能搞定的简单事你都要拆成网络调用？」对方可能只是说「这俩模块适合拆」，不是要你把 hello world 也微服务化。

## 一句话记住它

**复述对方观点 → 等对方确认 → 再反驳。** 这一个动作，能干掉九成的稻草人。
